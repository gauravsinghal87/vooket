# Current Architecture — Financial Systems

Audit-only document. Generated by repository inspection. No code changes made.

## 1. Application layout

- Laravel backend: `backend/` (http://localhost:8001 in dev; `.env` APP_URL http://localhost:8000).
- Customer web: `customer-web/`
- Admin web: `admin-web/`
- Vendor web: `vendor-web/`
- Partner web: `partner-web/`
- Customer mobile: `customer-app/` (React Native) — locate via `customer-app/package.json`.
- Database engine: MySQL (`DB_CONNECTION=mysql`, `DB_DATABASE=vooket`, root, no password in local). Tests use SQLite in-memory (`phpunit.xml`: `DB_CONNECTION=sqlite`, `DB_DATABASE=:memory:`).

## 3. Core financial services

- `App\Services\PaymentService` — initiate/verify/capture payments, webhooks.
- `App\Services\WalletService` — credit/debit/reserve/finalize/release/adjust, ledger entries.
- `App\Services\RefundService` — request/approve/process/reject, cancelled/delivered order refunds, reconcile.
- `App\Services\CommissionService` — calculate/finalize vendor commission for orders.
- `App\Services\WithdrawalService` — vendor/driver/partner/wallet payout requests + mark success/failed.
- `App\Services\DeliveryService` — delivery lifecycle, partner earnings, cash collection/settlement, cancellation/unwind.
- `App\Services\RideService` — fare estimate, ride create/cancel/complete, cash collection/settlement.
- `App\Services\CouponService`, `InventoryService`, `DeliveryFeeService`, `GroceryDeliveryConfigService`, `DeliverySlotService`.

## 4. Payment providers

- `app/Infrastructure/Providers/Payments/RazorpayProvider.php` (real), `MockPaymentProvider.php` (local/testing only, guarded by `assertGatewayUsable()`).
- `RazorpayRouteProvider.php` (Razorpay Route?).
- Gateway resolved via `app(PaymentGatewayInterface::class)`; gateway name 'mock' or 'razorpay'.
- Webhooks: `POST /api/webhooks/razorpay` -> `PaymentWebhookController`.

## 5. Account types & wallets

Single `wallets` table shared by customer/driver/delivery_partner/vendor/platform (`wallet_type`). `wallets.balance` is a stored cached balance updated on credit/debit. `pending_balance` reserves withdrawals. Authoritative-ish but mutable cached; ledger_entries are single-sided (one row per transaction, not double-entry pairs).

## 6. Frontend financial data sources (summary)

- Admin: `DashboardController::index` -> counts/today_revenue/total_revenue (sums order.total_amount where payment_status != 'failed'); revenue series; top vendors.
- Admin refunds/payouts/support tickets endpoints.
- Vendor: `Vendor\EarningsController` (overview/settlements/payouts).
- Partner/driver: earnings/withdrawals/wallet endpoints.
- Customer: order payment, support ticket, wallet.
